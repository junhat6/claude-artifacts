npm と aqua、
ツールを入れる仕組み

npm は、公開されたプログラムを取得して使えるようにする道具です。Node.js は、JavaScript で書かれたプログラムを動かします。aqua は、あなたの OS と CPU に合った実行ファイルを取得します。

パソコンの基本機能を管理する仕組みが OS です。Mac では macOS がその役割を担います。計算処理を行う部品が CPU です。今回の「実行ファイル」は、Mac が起動できる形に用意されたプログラムを指します。

2026年10月8日確認 · Apple Silicon の Mac と、今回の mise 設定を例にしています。

入れる役割と、動かす役割を分ける

npm
プログラムを取得し、そのプログラムが使う別のプログラムも一緒にそろえます。こうした取得・更新・削除を扱う道具をパッケージマネージャーと呼びます。
npm は、コマンドの名前でも、プログラムの配布サービスの名前でもあります。
Node.js
JavaScript という言語で書かれたプログラムを、インターネット上の文書を表示するブラウザの外で動かします。プログラムの実行に必要な仕組みをランタイムと呼びます。
npm 自体も Node.js で動きます。
mise
どのツールの、どのバージョンを使うかを設定で管理します。バージョンは、公開された版を区別する名前や番号です。取得方法は npm: や aqua: などから選べます。
mise は、取得する方法と、使用するバージョンをまとめて管理します。

役割の根拠：npm 公式 · Node.js 公式 · mise の取得方法

なぜ npm でツールを入れられるのか

用途に沿って使うプログラムを、ここでは アプリ と呼びます。プログラムの動作を記述した命令が コード です。

npm では、プログラムと、その名前・バージョン・必要な部品をまとめて配布します。この配布単位をパッケージと呼びます。部品として組み込むプログラムだけでなく、ターミナルから使うツールも配布できます。

作者が「このファイルを、このコマンド名で起動する」と指定しておくと、npm がそのコマンドを使えるように配置します。ツールが使う別のパッケージも、作者の指定に合わせて取得します。こうした別のパッケージとの関係が依存関係です。

npm が必要かどうかは、
作者の配布方法と、ツールの動き方で決まります。

npm からだけ配布され、Node.js で動くツールなら、npm 系の取得方法が自然です。一方、作者が OS ごとの実行ファイルを公開していれば、aqua などで直接取得できる場合があります。

CPU が直接実行できる形に用意されたプログラムをネイティブ版と呼びます。npm からネイティブ版を配布することもできます。今回の Codex と、現在の Claude Code がその例です。ネイティブ版でも、OS の機能や、別のプログラムの部品が必要な場合はあります。

自分がコマンドとして使う

npm install -g czg

-g は、開発中のアプリの外で使うための指定です。実際にコマンドを見つけるには、保存先がコマンドを実行するときの検索対象に入っている必要があります。その検索先の一覧を PATH と呼びます。

開発中のアプリに部品を入れる

npm install lodash

これは、数値や文字の集まりを加工する部品の lodash を入れる説明用の例です。アプリが使う部品を、そのアプリのファイル群に追加します。ツールを普段使いするためのインストールとは、管理する場所と目的が違います。

根拠：コマンドの指定 · 依存関係 · Claude Code の npm 版

今回の Codex は、起動先が欠けていた

Missing optional dependency @openai/codex-darwin-arm64

Apple Silicon に対応する CPU の種類は arm64 と表記されます。Mac 用の配布物では、OS を darwin や macos と表すことがあります。darwin-arm64 は、この二つを組み合わせた環境の名前です。

npm 版 Codex 0.161.0 は、起動用の JavaScript と、OS・CPU ごとの実行ファイルを別のパッケージとして配布していました。あなたの Mac では、起動用のファイルはあるのに、Apple Silicon 用の実行ファイルが見つからず停止しました。

optional dependency は、取得に失敗しても全体のインストールを続けられる依存パッケージです。別の OS や CPU 用の、不要な版を入れずに済む仕組みですが、自分の環境用の版は実行に必要です。

  • この Mac の CPU は arm64 で、Node.js もその CPU 用の版でした。
  • 0.161.0 の取得記録には、必要な darwin-arm64 がありませんでした。
  • aqua から Apple Silicon 用の配布ファイルを取得すると、Codex は起動しました。

aqua 経由では、npm 側で OS 別の依存パッケージをそろえる手順を経ずに取得できます。ただし、元の欠落が「配布情報・取得情報の一時保存・mise/aube による依存パッケージの選択」のどこで起きたかは、今回の記録だけでは断定できません。

この節の根拠は、今回の Mac 内の調査と起動確認です。optional dependency の仕組み：npm 公式

別の言語で作られたツールにも、専用の方法がある

プログラムを書く言語には、JavaScript のほかに Python・Rust・Go などがあります。Python のツールなら pipx などで、ツールごとに必要な部品を分けて入れられます。Rust なら Cargo、Go なら go install でプログラムを実行ファイルに作り直して入れられます。この作業をビルドと呼びます。mise にも pipx:、cargo:、go: があります。

完成した実行ファイルが用意されているなら、それを取得すればビルドの手間を省けます。ただし、どの OS・CPU に対応するかはツールごとに違います。

根拠：pipx · Cargo · go install

名前には、どんな背景があるのか

名前そのものの意味と、作者がその名前を選んだ理由は分けて確認しました。公式に説明されている由来と、資料からの解釈を区別して載せています。

Node.js：通信でつながる「接続点」

node は、何かがつながる点を表す英語です。コンピューターの通信では、つながった機器や、処理を担う一つのプログラムを node と呼ぶことがあります。

作者の Ryan Dahl は2011年のインタビューで、Node を複数のプログラムが通信しながら大きな処理を行うための土台と説明し、それらを「nodes」と呼んでいます。一つの処理を担う接続点を作り、それらをつなぐという考え方と結び付けて、名前を理解できます。

これは作者の説明からの解釈です。このインタビューには「この理由で Node と命名した」という明言はないため、命名理由として断定はしていません。.js は JavaScript を連想させる表記ですが、ここで特定のファイルを指しているわけではありません。

単語の意味：Merriam-Webster · 作者の説明：Ryan Dahl インタビューの保存版（2011年1月31日）

aqua：単語は「水」、採用理由は未確認

aqua はラテン語に由来する「水」を表す単語です。ただし、このツールの作者が何を意図して aqua という名前を選んだのかは、今回確認した公式の紹介文・よくある質問と回答・作者の紹介記事には説明がありませんでした。

そのため、単語の意味は確認済み、ツールの命名理由は未確認としています。単語の意味だけで、作者がこの名前を選んだ理由までは分かりません。

単語の意味：Merriam-Webster · 確認した資料：公式の紹介文 · 公式のよくある質問と回答 · 作者の紹介記事

mise：料理を始める前に準備を整える

mise は、フランス語の mise-en-place に由来します。料理を始める前に、材料や道具を使える状態にそろえておくことを表します。

開発でも、作業の前にツール・設定・コマンドを用意します。料理の準備と、開発環境の準備を重ねた名前です。この由来は公式サイトで説明されています。

由来：mise 公式 About

npm：「Node Package Manager」の略ではない

役割から npm を Node Package Manager の略だと思いやすいのですが、公式の紹介文 はその説明を否定しています。前身は、プログラムを入れるための pm という道具で、その名前は pkgmakeinst を短くしたものでした。公式の紹介文は、名前を略として読む場合の候補として node pm や new pm も挙げています。ただし、どちらかを正式名称とする説明ではありません。

公式には、npm is not an acronym、つまり「npm は頭文字を並べた略語ではない」という言葉遊びも紹介されています。機能はパッケージ管理ですが、名前の由来を単純に Node Package Manager と説明すると正確ではありません。

由来：npm 公式の紹介文の名前についての説明

pnpm：「効率よく動く npm」

pnpm は performant npm の略です。performant は、性能がよく効率的に動くことを表します。名前を考えたのは @rstacruz で、この点も公式のよくある質問と回答 に記載されています。

由来：pnpm 公式のよくある質問と回答

npm を維持

czg と Cloudflare の cf
czg は変更履歴に添える説明文を作るツールです。cf は、インターネット上のページなどの公開・運用を支援する Cloudflare のサービスを操作します。どちらも、今回確認したインストールでは Node.js を使います。npm の配布を利用する方法が自然です。

mise の短い名前 cf は 別の製品のツールを指します。Cloudflare の方は npm:cf と明示します。

[tools]
"aqua:anthropics/claude-code" = { version = "latest", minimum_release_age = "0s" }
"aqua:openai/codex" = { version = "latest", minimum_release_age = "1h", os = ["macos/arm64"] }
"npm:czg" = "1.14.0"
"npm:cf" = "latest"

latest は、条件に合う最新の版を選ぶ指定です。minimum_release_age は公開後に待つ時間で、1h は1時間、0s は待たずに選ぶ指定です。os = ["macos/arm64"] は、このツールをその環境だけで有効にする条件です。OS 別の依存パッケージを強制的に選び直す設定ではありません。

混ざりやすい疑問

全部 aqua にそろえた方がよい？

ツールの配布方法に合わせて選びます。JavaScript の部品を npm から取得する仕事は、aqua では置き換えられません。mise の中で npm と aqua を併用して問題ありません。

npm で入れるなら、実行にも npm が必要？

npm は取得する役割です。JavaScript のツールなら実行時に Node.js が必要です。ネイティブ版なら、実行時に Node.js を必要としないことがあります。今回の npm 版 Codex は、起動用 JavaScript に Node.js を使っていました。現在の Claude Code の npm 版は、取得後にネイティブ版を直接起動します。

mise の npm: は、必ず npm コマンドを呼ぶ？

必ずではありません。現在の mise は、標準で内蔵の aube を使って取得します。そのため、取得するだけなら Node.js や npm が別途なくても動きます。ただし、取得したツールが Node.js を必要とするなら、実行のために Node.js を用意します。mise 公式

aqua 自体もインストールする必要がある？

mise の aqua 経由を使うときは不要です。mise 自身が aqua の登録情報を読み、配布ファイルを取得します。aqua という独立したツールもありますが、今回の運用ではそれを起動しません。mise 公式

npx は何をするもの？

npm パッケージのコマンドを、その場で実行する入口です。手元に必要なパッケージがない場合は、取得して保存してから実行します。「取得せずに動く」という意味ではありません。npm 公式

Homebrew と mise はどちらを使う？

現在の dotfiles は、画面を操作して使うアプリや共通の部品を Homebrew、ランタイムや開発用のコマンドを mise で管理する方針です。mise はツールの版を設定に残し、開発するアプリごとに使い分けたい場合に向いています。今回もこの方針に合わせています。
